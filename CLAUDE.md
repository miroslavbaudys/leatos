# CLAUDE.md

rrouter is a SOHO router OS in Rust: a **bare-metal unikernel** for aarch64 (QEMU `virt`, HVF on Apple Silicon) and x86_64 (QEMU q35 via PVH, TCG; target hardware: PC Engines apu4, M10).
Goals: PPPoE, DHCP (v4 server/client, DHCPv6-PD, RA), a DNS forwarder, NAT, a firewall, IPv4 + IPv6, and
**bufferbloat mitigation with CAKE**, which is a core design driver (`docs/bufferbloat-cake.md`).

## Layout
- `kernel/` (`rrouter-kernel`, binary `rrouter`)
  - `src/main.rs`: arch-neutral boot order (`kmain`). `#![deny(unsafe_code)]` applies crate-wide
  - `src/arch/`: **all** CPU-specific code. `aarch64/` (boot.S, cpu, exceptions + IRQ entry, irqchip = GICv3, timer, mmu descriptors, power = PSCI, console = PL011, smp = PSCI `CPU_ON`; kexec/rtc/watchdog are stubs) and `x86_64/` (boot.S = PVH + Multiboot2 entry → long mode, AP trampoline, isr.S, exceptions = IDT/TSS/IST, irqchip = local APIC + MSI-X (+ one IOAPIC entry: COM1's ISA IRQ 4, MADT only), timer = TSC + LAPIC one-shot, power = ACPI S5, console = 16550, port I/O, rtc = CMOS clock (time registers only), smp = INIT-SIPI-SIPI, kexec (+ kexec.S), watchdog = AMD FCH). `arch/mod.rs` documents the API every backend provides
  - `src/platform/`: neutral `BootInfo` (no allocation); `dtb.rs` (aarch64); `pvh.rs` / `multiboot2.rs` + `acpi.rs` over `phys.rs` (x86_64: one unsafe byte-view constructor, safe parsers)
  - Ports: `wan0` + LAN ports `lan0`–`lan2` (NICs in PCI order, `config::PORTS`, at most `shared::MAX_PORTS`); routed ports, no bridge: each network is on one port (`network.ports`), `LinkShared::port` set live with the VID; networks on a port the machine lacks are left out (`config::missing_networks`)
- `src/smp.rs`: multicore (docs/smp.md): `start` (secondary cores via `arch::smp::start`: aarch64 PSCI `CPU_ON`, x86_64 INIT-SIPI-SIPI into the `boot.S` trampoline at 0x8000), `secondary_main`, `current()`, `wake(core)` (IPI), `stop_others`; boot argument `cores=N`. Tasks are pinned (`executor::spawn_on`; `net::stack::layout`): with ≥ 3 cores `dp_down` on 0, `dp_up` on 1, `svc` on 2; with 2 both directions on 0 and `svc` on 1; `dp_down` receives on wan0 and sends on every LAN port, `dp_up` the reverse (`stack::PortSet`)
  - `src/mm/`: `stacks` (secondary cores' stacks from `__ap_stacks`, guard pages), `heap`, `mmu` (neutral page-table builder; arch supplies the encoding), `dma` (virtio `Hal`), `sym` (linker symbols)
  - `src/mmio.rs`: `Region` = safe, bounds-checked MMIO over `safe-mmio`
  - `src/fatal.rs` (every fatal path: stop the other cores, 3 s, reset; `panic=halt` halts), `src/watchdog.rs` (cross-core check: a `watchdog` task per core, a core unseen for 5 s is reported and reset; pets the hardware watchdog `drivers::watchdog` = i6300esb in QEMU, AMD FCH on the apu4 in `arch/x86_64/watchdog.rs`), `src/entropy.rs` (SHA-256 pool from timing jitter, boot data, MACs, request arrival times; no hardware RNG trusted), `src/wallclock.rs` (UTC from SNTP; RTC read at boot as a hint only, set after each sync: `arch::rtc`), `src/cli.rs` (serial CLI inside `svc`: reads `console`'s RX ring line by line, `status`, `leases`, `routes`, `log [N|all|clear]`, `config show [running|stored|pending]`, `config set/unset/diff/save/discard` as TOML assignments on a pending copy, `reboot`)
  - `src/irq.rs` (dispatch + `IrqEvent`; shared INTx lines: sharers, `line_done`), `timer.rs` (tickless, `sleep`), `executor.rs` (priority async; accounts idle and per-priority poll time), `cpuload.rs` (1 s CPU load samples, 5 min history, shown on the mgmt page), `console.rs` (`println!`, `fatal_println!`; the CLI's input line is redrawn after other output; UART RX interrupt → lock-free ring; once the CLI is up, log messages go to a 64 KiB RAM log (`log=console` keeps them on the UART; fatal paths dump its tail)), `pci.rs` (via `virtio-drivers` `PciRoot`), `selftest.rs`
  - `src/drivers/`: `Nic` (the one NIC interface the stack uses), `virtio_net.rs` (slot-owned DMA buffers, pull-based TX with a byte limit), `igb.rs` (i210/i211 + QEMU's 82576: own descriptor rings in `mm::dma::DmaRegion`, INTx or MSI-X, same TX contract), `virtio_blk.rs` (store disk in QEMU: polled, one driver-owned request in flight, yields while waiting), `sdhci.rs` (SD card behind a standard SDHCI, the apu4's slot at 00:14.7: PIO, polled, yields), `Disk` (the one block interface the store uses), `watchdog.rs` (`HwWatchdog` + probe), `i6300esb.rs` (QEMU's PCI watchdog), `cputemp.rs` (AMD family 16h die temperature from PCI 00:18.3 D18F3xA4 + HTC limit x64, k10temp's decoding; sampled with `cpuload`, `/api/status` `temp` (null without a sensor, e.g. QEMU), overview tile + chart, CLI `status`)
  - `src/net/`: `packet.rs` (bounded pool, headroom, `PacketMeta`, `pop_vlan`/`push_vlan`), `datapath.rs` (NIC RX → VLAN check/untag → PPPoE decap → `fwd::Forwarder` → (from the WAN: ingress qdisc, `drain_ingress`) → neighbor (PPPoE: the AC) → qdisc → PPPoE encap → VLAN tag → NIC TX; PPPoE control frames → `ctrl_rx`), `device.rs` (smoltcp `Device` behind the datapath: RX from `local_rx`, TX into the qdisc), `stack.rs` (port bring-up + the **datapath direction tasks** `dp_down`/`dp_up` (`run_dir`): NAPI-style IRQ loop; lock order NIC → forwarder shard → neighbor table → qdisc), `svc.rs` (the **services task** `svc`, `Priority::Service`: smoltcp, WAN DHCP client (smoltcp's `dhcpv4` socket) or PPPoE, LAN services, mgmt; a saved WAN change restarts the WAN live, DHCP ⇄ PPPoE included), `pppoe.rs` (svc side of `proto_pppoe::Client`: `ctrl_rx` in, frames into the WAN qdisc, `Session` → `PortShared::pppoe_session`, up/down → router-stack address + `LeaseChange`; the WAN interface is `Medium::Ip` in PPPoE mode; PADT at reboot/upgrade from the datapath), `shared.rs` (the only coupling between them: per-port locked qdisc + PPPoE `ctrl_rx`/`pppoe_session`, stats snapshot; per-**link** `local_rx` (`LinkShared`: link 0 = WAN on port 0, links 1..`MAX_LINKS` = network slots on `lan0`, created at boot, switched on/retagged/readdressed live (`assign_slots`, `Networks` → `Datapath::apply`); forwarder interfaces, ARP tables and smoltcp interfaces are per link, a VLAN network's tag is pushed when a frame is queued on the port); `Control` messages (WAN lease, zone `Policy`, reboot/exec), `dp_kick`/`svc_kick` events), `services.rs` (per network a DHCP server + DNS socket, one resolver/zone: smoltcp UDP sockets ↔ sans-IO crates), `dns_tcp.rs` (DNS over TCP from clients, RFC 7766: 4 TCP :53 sockets per network, length-prefixed queries → `Resolver::handle_query_tcp`, answers by client endpoint, pipelining, bounded buffers, 10 s idle close; `/api/status` `dns.tcp`), `ntp.rs` (SNTP client on the WAN; names resolved through the forwarder as client `127.0.0.1:1`), `dot.rs` (DNS over TLS, docs/dns-over-tls.md: one `proto_dot::Conn` per `dns.upstreams` server over a smoltcp TCP socket on the WAN (local ports 61000–64999), opened on demand, 30 s idle close, backoff on failure, reconnect once SNTP sets the clock; strict: with `dns.tls` no UDP upstream query and UDP answers ignored; entropy from `entropy`, clock `wallclock`, build time floor `RROUTER_BUILD_TIME`), `mdns.rs` (mDNS reflector glue inside `LanServices`: joins 224.0.0.251 (smoltcp `multicast`) and a 5353 socket per network a `[[mdns.reflect]]` entry involves, `proto_mdns::Reflector`, counters in `/api/status` `mdns` and CLI `status`)
  - `src/net/mgmt.rs` + `mgmt.html`: management web interface on :80 (one hash-routed page: overview, interfaces, clients, WAN, networks (VLANs, zone, DHCP per network), routes (table in use + `[[route]]` list), LAN & DHCP, DNS (upstreams, local names: `dns.views` + `[[dns.host]]` table), firewall (zones, rules, port forwards, redirects, mDNS reflect rules with warnings and counters), shaping, system, logs; pending changes with a diff, a login screen covering the page (LuCI-style) via `POST /api/login` (session token in `localStorage`; a 401 brings the screen back and the request is retried; `X-Rrouter-UI: 1` suppresses `WWW-Authenticate`), with a password everything but `/` and `GET /api/info` (`{auth}`) needs auth, reads included (scripts: `curl -u admin:…`), without one reads are public and changes refused, `GET /api/log` (RAM log, auth), `GET /api/status` (incl. `drop_reasons`, `mgmt.auth`, `routes`), `POST /api/upgrade` streamed into the staging area, `POST /api/upgrade/persist` (stored as a trial, reboot) + `/api/upgrade/confirm|revert`, `POST /api/reboot`, `GET /api/config[.json]`, `GET /api/config/effective[.json]` (boot arguments applied: for moving them into the config), `POST /api/config` (TOML or JSON; validate, save to the store, then apply live: `config::apply`, `stack::apply_qos`, `LanServices::reconfigure`; trials reboot), `POST /api/config/confirm|revert` (trials: LAN/management changes boot as a trial that reverts without confirm, docs/config-and-storage.md §6); the page has a config form with import/export; auth: `POST /api/login` (Basic `admin` + `mgmt_pass=` boot argument, else the config's `mgmt.password_hash` via `crates/auth` PBKDF2, cached) returns a session token used as `Authorization: Bearer`, `POST /api/logout`; a wrong password blocks for 1 s; a saved clear `mgmt.password` is hashed first (`Config::hash_new_password`, salt from `kernel/src/entropy.rs`) and ends all sessions)
  - `src/upgrade.rs`: kernel upgrades (docs/upgrades.md; x86_64 only). In RAM: validate + flatten an uploaded kernel in the staging area at the top of RAM (`mm::heap::take_staging`); `arch::kexec` copies it into place and enters it like a Multiboot2 loader. Persistent: kernels in the store's `images` area as trial records; `upgrade::boot` (in `kmain` after the store, before `config::load`) makes the boot partition's kernel the loader: it enters the current stored kernel (`image=<slot>:<seq>` added), marks trials booted and rolls back one found already booted; `image=golden` skips it, `image=ram` marks an in-RAM upgrade. Confirm/revert via `/api/upgrade/confirm|revert`, else reverted after `trial_secs`
  - `src/config.rs`: one `config::Config` (`crates/config`) built at boot by `config::load(store)` (after PCI, so it can read the disk): defaults ← stored `config.toml` ← boot arguments (`config=defaults` ignores the store); `lan()`/`dns()`/`qos()`/`mgmt()` are views of it, `base()` is it without boot arguments. Without a stored config, on virtual machines only, the lab's `nas` reservation (host .10) is added. `overrides()` lists the fields boot arguments set (shown on the form)
  - `src/store.rs`: the store partition (MBR type 0xda + valid store header, never formatted by the kernel) on a block device: async record read/write via `crates/config-store`, boot reads through `executor::block_on`; saves run in `svc`. DHCP leases live in the `leases` area (`net/svc.rs` `LeaseStore`: restored at boot, written when the bound set changes (checked every 60 s) and before reboot/upgrade; format `proto_dhcp::v4::persist`)
  - `linker.ld` (aarch64, kernel at `0x4020_0000`) / `linker-x86_64.ld` (at 1 MiB, keeps the PVH note): page-aligned sections, guard pages, 16 KiB exception stack + 256 KiB kernel stack

## Commands
- `cargo kbuild [--release]`: build the kernel. `cargo krun` boots it (`Ctrl-A X` quits; `QEMU_NET=user` adds 2 NICs)
- `scripts/smoke-test.sh`: cases boot (DHCP + ping), fault-wx, fault-stack, panic (reboots), wdt-task (cross-core watchdog, 2+ cores), wdt-hw (i6300esb with `cores=1`); negative controls `QEMU_APPEND=panic=halt`, `QEMU_APPEND=watchdog=0`, `QEMU_WDT=0`. QEMU gets `-device i6300esb` unless `QEMU_WDT=0`. Also run `QEMU_ACCEL=tcg scripts/smoke-test.sh` after boot, MMU, IRQ, timer or driver changes
- `scripts/lab-test.sh`: client VM + router + ISP VM; DHCP, DNS (incl. cache prefetch: ISP TTL 12 s, negative control `LAB_ROUTER_ARGS=dns_prefetch=0`; serve-stale with the ISP's DNS stopped via `cgi-bin/dns` / `lab-dns`, plus EDE 3 on a crafted EDNS query, negative control `LAB_ROUTER_ARGS=dns_stale=0`; DNS over TCP: big.isp.example (850 B TXT from the ISP's cacheless dnsmasq in front of dnsd) truncated over UDP, whole over TCP, negative control `LAB_ROUTER_ARGS=dns_tcp=0`), NAT, ICMP (also full-size: `LAB_BIG_PING=1473 LAB_ROUTER_ARGS=fw_frag=0` is its negative control; fragmented `ping -s 3000` both ways, negative control `LAB_ROUTER_ARGS=fw_frag=0`; over PPPoE the router splits the 1500 B fragments, checked by `fragments.split`, negative control `fw_split=0`), `LAB_WAN_STATIC=1` (the ISP runs no DHCP server, the router gets `wan_mode=static wan_ip=203.0.113.60/24 …`: static line + NATed source 203.0.113.60, all checks through it; negative control `LAB_ROUTER_ARGS=wan_mode=dhcp`), `LAB_PPPOE=pap|chap|none` (ISP = rp-pppoe `pppoe-server` only, user mode; `none` = no authentication and no router user name, negative control `LAB_PPPOE=pap LAB_PPPOE_ANON=1`; all checks through the session + reconnect after the ISP ends it; negative controls `LAB_ROUTER_ARGS=pppoe_pass=wrong` / `wan_mode=dhcp`, `LAB_PPPOE_KICK=stop`, `LAB_BIG_PING=1465 LAB_ROUTER_ARGS=fw_frag=0` (1465 alone passes: the client's DF ping learns MTU 1492 and fragments itself); combines with `LAB_VLAN=848`), traceroute, firewall end to end, WAN input silent to the ISP's probes (TCP 22, 80, 61000, ping; negative controls `LAB_ROUTER_ARGS=mgmt=wan`, `LAB_WAN_OPEN=1` = a rule accepting wan → router), plus router-side ECN, SNTP from the ISP's ntpd (±5 s of the host; negative control `LAB_ROUTER_ARGS=ntp=203.0.113.99`), the per-task CPU split (`dp_down`, `dp_up` vs `svc`, over the client's load phase from `/api/status` `cpu.tasks`) and their core placement (`LAB_VERBOSE=1` for consoles). Run it after any network change, also with `QEMU_ACCEL=tcg`
- `scripts/apu-upload.sh [--host H] [--cmdline "..."] [--debug] [--reboot] [--persist [--no-confirm]] [--confirm | --revert]`: build + strip the x86_64 kernel and upgrade a running rrouter over HTTP, in RAM, or with `--persist` stored on the SD card as a trial, rebooted into and confirmed once that trial (its seq) has stayed up for `--stable-secs`, default 30 (password from `target/apu4/mgmt-pass`). `scripts/upgrade-test.sh`: the in-RAM upgrade end to end in QEMU (401/422/404 negative controls, two chained upgrades, reboot); `scripts/persist-test.sh` (also `QEMU_STORE_BUS=sd`): persistent upgrades, confirm, rollbacks (panic, hang, no confirm, revert, kill), `image=golden`, corrupt record (negative control `PERSIST_TEST_CONTROL=no-confirm`). Run both after changes to mgmt, upgrade, kexec, store, watchdog, boot or the x86 NIC path
- `scripts/apu-image.sh [--debug] [--mgmt-pass | --mgmt-wan] [--config FILE] [--cmdline "..."]`: bootable image for the apu4 (`--config` seeds the store, validated; the apu4's config lives in `target/apu4/config.toml`, so the command line needs only `mgmt_pass=`) (`target/apu4/rrouter-apu4.img`; needs `brew install limine mtools`). `RROUTER_BOOT=limine scripts/smoke-test.sh` boots it through SeaBIOS + Limine in QEMU; run it after x86 boot or linker-script changes. `QEMU_DISK=img scripts/qemu-run.sh` boots any image
- `scripts/lease-test.sh` (also `RROUTER_ARCH=x86_64`, `QEMU_STORE_BUS=sd`): router + lab client: leases listed and resolvable after a power cut (router killed after its periodic save) and after `POST /api/reboot`; negative control `LEASE_TEST_NO_STORE=1`. Run it after DHCP, store or `svc` changes

## Rules
- **Never set `build.target` in `.cargo/config.toml`.** Use the `k*` aliases.
- **Arch boundary:** outside `kernel/src/arch/`, nothing may use `asm!`, `core::arch` or arch crates (`aarch64-cpu`). Neutral code calls only the `arch::` API. Keep `cargo kcheck-x86` passing.
- **Unsafe policy** (docs/safety-and-portability.md):
  - `unsafe` is denied crate-wide. A module may opt in only via `#[allow(unsafe_code)] // reason` on its `mod` line.
  - Prefer building a safe abstraction (`mmio::Region`, slot ownership, `PciRoot`) over spreading `unsafe`.
  - Every block needs `// SAFETY:` (denied otherwise), with one unsafe op per block.
  - `crates/*` are `#![forbid(unsafe_code)]`.
- `crates/*` are `#![no_std]` + `alloc` and **sans-IO** (pass bytes and `now` in; return bytes and events). Protocol logic goes there, not in the kernel.
- Dependencies must be `no_std`. Prefer audited crates (virtio-drivers, safe-mmio, smoltcp, aarch64-cpu) over hand-written unsafe.
- Edition 2024: `#[unsafe(no_mangle)]`, `unsafe extern "C"`, `&raw const`.
- Kernel runtime options are **boot arguments** (DTB `/chosen/bootargs`, QEMU `-append` via `QEMU_APPEND`), parsed in `config.rs`: `shape_up`, `shape_down`, `shape_overhead`, `shape_ingress=0` (download shaped on LAN egress as before 2026-11-19, which also caps traffic between networks: the lab's negative control for `lan to guest`), `ecn_up` (default 0: drop on upload), `ecn_down` (default 1: mark on download), `ecn` (sets both), `qdisc` (`cake` default, `fq_codel`, `codel` = single queue), `isolation` (`triple-isolate` default, `dual-srchost`, `dual-dsthost`, `flows`), `idle_spin_us`, `cores=N` (use at most N cores), `lan=a.b.c.d/len` (LAN subnet; pool .100–.199), `wan_vlan=N` (802.1Q tag on the WAN, `0` = untagged; `[wan] vlan`), `wan_pcp=0..7`, `wan_mode=pppoe|dhcp|static` (`[wan] mode`), `wan_ip=a.b.c.d/len`, `wan_gw=`, `wan_dns=a,b` (`[wan.static]`; without a stored one both `wan_ip=` and `wan_gw=` are needed), `pppoe_user=` (optional: empty = no authentication), `pppoe_pass=` (masked like `mgmt_pass=`), `pppoe_service=`, `pppoe_ac=`, `pppoe_mtu=` (`[wan.pppoe]`; up to 1500 = RFC 4638: PPP-Max-Payload in discovery, MRU 1500 only if the AC echoes it, a full-size LCP echo must pass, else back to 1492), `mgmt=wan` (web interface on the WAN too: development only), `mgmt_pass=` (enables upgrade/reboot/config save; masked in logs via `config::Redacted`), `config=defaults` (ignore the stored config: recovery), `image=golden` (ignore stored kernels: recovery; `image=` is otherwise set by the loader / in-RAM upgrade), `trial_secs=` (confirm window of a trial config, default 120; tests), `ntp=a,b` (SNTP servers; `ntp=` = off), `dns=ip#name,…` (`dns.upstreams`; `dns=` = the WAN lease's), `dns_tls=0|1` (`dns.tls`; strict fails closed: unnamed servers dropped), `dns_prefetch=0|1` (`dns.prefetch`, default on: cache hits in the last tenth of the TTL renew the entry), `dns_stale=SECS` (`dns.stale_secs`, serve-stale RFC 8767, default 86400, 0 = off), `dns_tcp=0` (no DNS over TCP from clients: the lab's negative control), `fw_recheck=0` (a new firewall policy leaves tracked connections alone: the lab's negative control), `fw_frag=0` (IP fragments dropped instead of forwarded: the lab's negative control), `fw_split=0` (non-DF packets above the egress MTU dropped as `too-big` instead of split: the lab's negative control), `wan_antispoof=0` (WAN packets from our own networks' or loopback sources are not dropped as `spoofed`: the lab's negative control), `conn_per_host=N` (connections one initiating host may hold, default a quarter of the 16384-entry table, `0` = no limit), `ct_bench=1` (time conntrack operations on a full synthetic table at boot: `selftest::conntrack_bench`), `watchdog=0` (no watchdog: gdb), `watchdog_secs=` (hardware timeout, default 30), `panic=halt` (halt instead of rebooting on panics and exceptions), `log=console` (log messages stay on the serial console after boot instead of the RAM log; `scripts/qemu-run.sh` adds it unless `QEMU_APPEND` sets `log=`). `scripts/lab-test.sh` passes extra ones via `LAB_ROUTER_ARGS` and checks per-direction ECN from the router's counters (`LAB_EXPECT_ECN=U:D` for the negative control). `LAB_VLAN=N` puts the ISP VM on VLAN N only (8021q from `modloop-virt`, `fetch-alpine.sh modloop`) and the router on `wan_vlan=N`; negative controls `LAB_ROUTER_ARGS=wan_vlan=0` / another VID.
- No heap use before `heap::init` (platform discovery runs before it). On x86_64, firmware memory (`platform::phys` views) is only valid during discovery: copy what you need into `BootInfo` or statics.
- New MMIO must be mapped in `mm::mmu::init` (or `arch::mmu::PLATFORM_MMIO`), or at runtime with `mm::mmu::map_device` (PCI BARs). Writable memory is never executable.
- Device interrupts: INTx where the platform routes it (aarch64), else MSI-X (`Pci::enable_msix`, vectors from `arch::irqchip::msi_vector`). Never add IOAPIC/INTx routing that needs ACPI AML.
- **Latency-first datapath (CAKE):** the qdisc is the only place packets may wait (no other FIFOs). TX is pull-based (`can_transmit` before `transmit`). Timers are tickless, so no periodic tick. Datapath tasks run at `Priority::Datapath`; router-local work (smoltcp, DHCP, DNS, mgmt, future services) runs in `Priority::Service` tasks and reaches the datapath only through `net::shared` (`spin::Mutex` + atomics, no `RefCell`, so tasks can move to other cores). Forwarded packets never leave the datapath task.
- **Ports:** NAT uses 10000–39999 (skipping forwarded ports); router-local client sockets (SNTP 60000–64999, DNS upstream 65000–65535, DoT TCP 61000–64999, future ones) must bind ≥ 60000 (`fwd::forwarder::ROUTER_CLIENT_PORTS`; TCP replies pass only from `Policy::router_tcp_peers`) so replies are never mistaken for NAT or port-forward traffic; port forwards may use anything below 60000 (validated).
- Never edit a script in place while it may be running (bash reads scripts incrementally): write a temp file and rename it over the original.
- Measurements must prove the load or condition actually happened (validity checks), or be reported as invalid.
- New lab checks need a **negative control** (show that the check fails when the feature is broken), as done for the firewall probe.
- **Packet buffers** come only from `net::packet` (bounded pool, no allocation per packet). On pool exhaustion, drop; never grow.
- **IRQ handlers** (`irq::register` actions) only acknowledge or mask hardware and touch atomics. No allocation, no `println!`, no locks except ones thread context takes with IRQs masked (the irqchip lock). Work runs in tasks awaiting an `IrqEvent`. Device interrupts follow NAPI: mask → poll until empty → unmask. INTx lines may be shared (QEMU `virt`: slots 4 and 8 on one line with three igbs): `irq::register` takes up to 4 sharers with one action, signals every sharer's event, and the line is unmasked only when `irq::line_done` says every sharer drained its device.
- Timer precision under QEMU/HVF comes from **hybrid idle** (`timer::set_spin_window`, 4 ms on virtual machines, 0 on hardware). Don't add other workarounds for `wfi` latency; `idle-poll` is only for experiments.
- Network changes on the developer's Mac: mac-lab only adds lab-scoped routes and resolvers. mac-internet may change routing and DNS, but only after confirmation, with the original state saved first, `/1` routes (never the default route), a watchdog, and `--restore`. Keep these guarantees in any new script.
- Lab downloads are pinned by SHA-256 in `scripts/lab/fetch-alpine.sh`; never unpin. Update the hashes deliberately.
- Shell scripts must run on macOS bash 3.2 (no associative arrays) and BSD tools (no `\s` in sed, no `timeout`).
- Update the status column in `docs/roadmap.md` when a milestone is done.
