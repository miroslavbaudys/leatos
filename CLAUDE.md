# CLAUDE.md

leatos is a SOHO router OS in Rust: a **bare-metal unikernel** for aarch64 (QEMU `virt`, HVF on Apple Silicon) and x86_64 (QEMU q35 via PVH, TCG; target hardware: PC Engines apu4, M10).
Formerly **rrouter** (renamed 2026-11-19). The old name stays where changing it would break something deployed: the store magics `RRSTORE1`/`RREC` (crates/config-store), `/boot/rrouter` on apu4 SD cards flashed before the rename (new images use `/boot/leatos`) and the `mac-lab.sh` resolver marker (old one still recognised).
Goals: PPPoE, DHCP (v4 server/client, DHCPv6-PD, RA), a DNS forwarder, NAT, a firewall, IPv4 + IPv6, and
**bufferbloat mitigation with CAKE**, which is a core design driver (`docs/bufferbloat-cake.md`).

## Layout
- `kernel/` (`leatos-kernel`, binary `leatos`)
  - `src/main.rs`: arch-neutral boot order (`kmain`). `#![deny(unsafe_code)]` applies crate-wide
  - `src/arch/`: **all** CPU-specific code. `aarch64/` (boot.S, cpu, exceptions + IRQ entry, irqchip = GICv3, timer, mmu descriptors, power = PSCI, console = PL011, smp = PSCI `CPU_ON`; kexec/rtc/watchdog are stubs) and `x86_64/` (boot.S = PVH + Multiboot2 entry → long mode, AP trampoline, isr.S, exceptions = IDT/TSS/IST, irqchip = local APIC + MSI-X (+ one IOAPIC entry: COM1's ISA IRQ 4, MADT only), timer = TSC + LAPIC one-shot, power = ACPI S5, console = 16550, port I/O, rtc = CMOS clock (time registers only), smp = INIT-SIPI-SIPI, kexec (+ kexec.S), watchdog = AMD FCH). `arch/mod.rs` documents the API every backend provides
  - `src/platform/`: neutral `BootInfo` (no allocation); `dtb.rs` (aarch64); `pvh.rs` / `multiboot2.rs` + `acpi.rs` over `phys.rs` (x86_64: one unsafe byte-view constructor, safe parsers)
  - Ports: `wan0` + LAN ports `lan0`–`lan2` (NICs in PCI order, `config::PORTS`, at most `shared::MAX_PORTS`); routed ports, no bridge: each network is on one port (`network.ports`), `LinkShared::port` set live with the VID; networks on a port the machine lacks are left out (`config::missing_networks`)
- `src/smp.rs`: multicore (docs/smp.md): `start` (secondary cores via `arch::smp::start`: aarch64 PSCI `CPU_ON`, x86_64 INIT-SIPI-SIPI into the `boot.S` trampoline at 0x8000), `secondary_main`, `current()`, `wake(core)` (IPI), `stop_others`; boot argument `cores=N`. Tasks are pinned (`executor::spawn_on`; `net::stack::layout`): with ≥ 3 cores `dp_down` on 0, `dp_up` on 1, `svc` on 2; with 2 both directions on 0 and `svc` on 1; `dp_down` receives on wan0 and sends on every LAN port, `dp_up` the reverse (`stack::PortSet`)
  - `src/mm/`: `stacks` (secondary cores' stacks from `__ap_stacks`, guard pages), `heap` (`talc`, boot argument `heap=list` = the old first-fit linked list, whose alloc/free walk every hole; every alloc/free timed: `/api/status` `heap.allocator`/`fragments`/`live`/`alloc`/`dealloc`/`lock_wait`, soak CSV columns), `mmu` (neutral page-table builder; arch supplies the encoding), `dma` (virtio `Hal`), `sym` (linker symbols)
  - `src/mmio.rs`: `Region` = safe, bounds-checked MMIO over `safe-mmio`
  - `src/fatal.rs` (every fatal path: stop the other cores, 3 s, reset; `panic=halt` halts), `src/watchdog.rs` (cross-core check: a `watchdog` task per core, a core unseen for 5 s is reported and reset; pets the hardware watchdog `drivers::watchdog` = i6300esb in QEMU, AMD FCH on the apu4 in `arch/x86_64/watchdog.rs`), `src/entropy.rs` (SHA-256 pool from timing jitter, boot data, MACs, request arrival times, the apu4's AMD CCP TRNG via `drivers/ccp.rs` (registers at BAR2 + 0x20000, health-checked, extra input only); RDRAND not used), `src/wallclock.rs` (UTC from SNTP; RTC read at boot as a hint only, set after each sync: `arch::rtc`), `src/cli.rs` (serial CLI inside `svc`: reads `console`'s RX ring line by line, `status`, `leases`, `routes`, `log [N|all|clear]`, `config show [running|stored|pending]`, `config set/unset/diff/save/discard` as TOML assignments on a pending copy, `reboot`)
  - `src/irq.rs` (dispatch + `IrqEvent`; shared INTx lines: sharers, `line_done`), `timer.rs` (tickless, `sleep`), `executor.rs` (priority async; accounts idle and per-priority poll time), `cpuload.rs` (1 s CPU load samples, 5 min history, shown on the mgmt page), `console.rs` (`println!`, `fatal_println!`; the CLI's input line is redrawn after other output; UART RX interrupt → lock-free ring; once the CLI is up, log messages go to a 64 KiB RAM log (`log=console` keeps them on the UART; fatal paths dump its tail)), `pci.rs` (via `virtio-drivers` `PciRoot`), `selftest.rs`
  - `src/drivers/`: `Nic` (the one NIC interface the stack uses), `virtio_net.rs` (slot-owned DMA buffers, pull-based TX with a byte limit), `igb.rs` (i210/i211 + QEMU's 82576: own descriptor rings in `mm::dma::DmaRegion`, INTx or MSI-X (self-masking via `EIAM`, no `ICR` read; TX completions on vector 1 to the transmitting core, armed only while TX is blocked: `arm_tx_irq`; RX moderation `igb_itr_us=`; 256-entry RX ring; NIC drops `MPC` + `RQDPC0` → `/api/status` `rx_missed`), same TX contract), `virtio_blk.rs` (store disk in QEMU: polled, one driver-owned request in flight, yields while waiting), `ccp.rs` (AMD CCP TRNG, PCI 1022:1537), `sdhci.rs` (SD card behind a standard SDHCI, the apu4's slot at 00:14.7: PIO, polled, yields), `Disk` (the one block interface the store uses), `watchdog.rs` (`HwWatchdog` + probe), `i6300esb.rs` (QEMU's PCI watchdog), `cputemp.rs` (AMD family 16h die temperature from PCI 00:18.3 D18F3xA4 + HTC limit x64, k10temp's decoding; sampled with `cpuload`, `/api/status` `temp` (null without a sensor, e.g. QEMU), overview tile + chart, CLI `status`)
  - `src/net/`: `packet.rs` (bounded pool, headroom, `PacketMeta`, `pop_vlan`/`push_vlan`), `datapath.rs` (NIC RX → VLAN check/untag → PPPoE decap → `fwd::Forwarder` → (from the WAN: ingress qdisc, `drain_ingress`) → neighbor (PPPoE: the AC) → qdisc → PPPoE encap → VLAN tag → NIC TX; PPPoE control frames → `ctrl_rx`), `device.rs` (smoltcp `Device` behind the datapath: RX from `local_rx`, TX into the qdisc; IPv6: notes RS (`LinkShared::rs_seen`) and helps smoltcp 0.14's ND: `NdHints` feed it a solicitation from each client (`fwd::wire::ipv6_neighbor_hint`), unicast NS go to the solicited-node group (`ipv6_ns_to_solicited`), docs/ipv6.md §2; IPv4 the same: an ARP reply from each client (`fwd::wire::ipv4_neighbor_hint`, `arp_hints=0` off), so the first answer to an address smoltcp has not seen (or evicted) is not dropped; smoltcp's neighbor cache is 256 per network (kernel feature `neigh-cache-256`, default; smoltcp's own 8 evicted entries on a home LAN)), `stack.rs` (port bring-up + the **datapath direction tasks** `dp_down`/`dp_up` (`run_dir`): NAPI-style IRQ loop; lock order NIC → forwarder shard → neighbor table → qdisc), `svc.rs` (the **services task** `svc`, `Priority::Service`: smoltcp, WAN DHCP client (smoltcp's `dhcpv4` socket) or PPPoE, LAN services, mgmt; a saved WAN change restarts the WAN live, DHCP ⇄ PPPoE included), `pppoe.rs` (svc side of `proto_pppoe::Client`: `ctrl_rx` in, frames into the WAN qdisc, `Session` → `PortShared::pppoe_session`, up/down → router-stack address + `LeaseChange`; the WAN interface is `Medium::Ip` in PPPoE mode; PADT at reboot/upgrade from the datapath), `shared.rs` (the only coupling between them: per-port locked qdisc + PPPoE `ctrl_rx`/`pppoe_session`, stats snapshot; per-**link** `local_rx` (`LinkShared`: link 0 = WAN on port 0, links 1..`MAX_LINKS` = network slots on `lan0`, created at boot, switched on/retagged/readdressed live (`assign_slots`, `Networks` → `Datapath::apply`); forwarder interfaces, ARP tables and smoltcp interfaces are per link, a VLAN network's tag is pushed when a frame is queued on the port); `Control` messages (WAN lease, zone `Policy`, reboot/exec), `dp_kick`/`svc_kick` events), `services.rs` (per network a DHCP server + DNS socket, one resolver/zone: smoltcp UDP sockets ↔ sans-IO crates; with IPv6 on an RA `Advertiser` per network, frames straight into the port qdisc, retired ones send a last RA), `dns_tcp.rs` (DNS over TCP from clients, RFC 7766: 4 TCP :53 sockets per network, framing in `proto_dns::tcp`, length-prefixed queries → `Resolver::handle_query_tcp`, answers by client endpoint, pipelining, bounded buffers, 10 s idle close; `/api/status` `dns.tcp`), `ntp.rs` (SNTP client on the WAN; names resolved through the forwarder as client `127.0.0.1:1`), `dot.rs` (DNS over TLS, docs/dns-over-tls.md: one `proto_dot::Conn` per `dns.upstreams` server over a smoltcp TCP socket on the WAN (local ports 61000–64999), opened on demand, 30 s idle close, backoff on failure, reconnect once SNTP sets the clock; strict: with `dns.tls` no UDP upstream query and UDP answers ignored; entropy from `entropy`, clock `wallclock`, build time floor `LEATOS_BUILD_TIME`), `wan6.rs` (the WAN's IPv6, docs/ipv6.md steps 3–5a: the WAN's own address `config::wan_address6` (::1 in the prefix's last /64), the ISP's IPv6 DNS servers after the lease's (`LanServices::set_dns6`), the last prefix asked for again after a restart (lease record v2, `pd_keep=0` off); the ISP's RA (default router; `NdHints::take_ra`), router solicitations, `proto_dhcp::v6::pd::Client` on UDP :546; `wan6::state` feeds `config::wan6`/`gua_router`, changes reapply the networks (`svc::reapply_networks`); on PPPoE while IPv6CP is up (`set_ppp_link` from `net::pppoe`: the WAN link-local address, `Forwarder::set_ll6`, default router = the RA's or the IPv6CP peer); not with the `wan6_*`/`lan6_prefix` boot arguments), `mdns.rs` (mDNS reflector glue inside `LanServices`: joins 224.0.0.251 (smoltcp `multicast`) and a 5353 socket per network a `[[mdns.reflect]]` entry involves, `proto_mdns::Reflector`, counters in `/api/status` `mdns` and CLI `status`)
  - `src/net/mgmt.rs` + `mgmt.html`: management web interface on :80 (one hash-routed page: overview, interfaces, clients, WAN, networks (VLANs, zone, DHCP per network), routes (table in use + `[[route]]` list), LAN & DHCP, DNS (upstreams, local names: `dns.views` + `[[dns.host]]` table), firewall (zones, rules, port forwards, redirects, mDNS reflect rules with warnings and counters), shaping, system, logs; the page has a config form with import/export; auth: `POST /api/login` (Basic `admin` + `mgmt_pass=` boot argument, else the config's `mgmt.password_hash` via `crates/auth` PBKDF2, cached) returns a session token used as `Authorization: Bearer`, `POST /api/logout`; wrong passwords back off their source only (IPv4 address / IPv6 /64, 1 s doubling to 30 s, `auth::Throttle`), PBKDF2 checks ≤ 4/s in all; 8 connection slots per network, one kept listening by cutting the oldest head-less connection of the source holding most (`mgmt_evict=0` off), request head within 5 s; `/api/status` `mgmt.throttle`; a saved clear `mgmt.password` is hashed first (`Config::hash_new_password`, salt from `kernel/src/entropy.rs`) and ends all sessions)
  - `src/upgrade.rs`: kernel upgrades (docs/upgrades.md; x86_64 only). In RAM: validate + flatten an uploaded kernel in the staging area at the top of RAM (`mm::heap::take_staging`); `arch::kexec` copies it into place and enters it like a Multiboot2 loader. Persistent: kernels in the store's `images` area as trial records; `upgrade::boot` (in `kmain` after the store, before `config::load`) makes the boot partition's kernel the loader: it enters the current stored kernel (`image=<slot>:<seq>` added), marks trials booted and rolls back one found already booted; `image=golden` skips it, `image=ram` marks an in-RAM upgrade. Confirm/revert via `/api/upgrade/confirm|revert`, else reverted after `trial_secs`
  - `src/config.rs`: one `config::Config` (`crates/config`) built at boot by `config::load(store)` (after PCI, so it can read the disk): defaults ← stored `config.toml` ← boot arguments (`config=defaults` ignores the store); `lan()`/`dns()`/`qos()`/`mgmt()` are views of it, `base()` is it without boot arguments. Without a stored config, on virtual machines only, the lab's `nas` reservation (host .10) is added. `overrides()` lists the fields boot arguments set (shown on the form)
  - `src/store.rs`: the store partition (MBR type 0xda + valid store header, never formatted by the kernel) on a block device: async record read/write via `crates/config-store`, boot reads through `executor::block_on`; saves run in `svc`. DHCP leases live in the `leases` area (`net/svc.rs` `LeaseStore`: restored at boot, written when the bound set changes (checked every 60 s) and before reboot/upgrade; format `proto_dhcp::v4::persist`)
  - `linker.ld` (aarch64, kernel at `0x4020_0000`) / `linker-x86_64.ld` (at 1 MiB, keeps the PVH note): page-aligned sections, guard pages, 16 KiB exception stack + 256 KiB kernel stack

## Rules
- **Never set `build.target` in `.cargo/config.toml`.** Use the `k*` aliases.
- **Arch boundary:** outside `kernel/src/arch/`, nothing may use `asm!`, `core::arch` or arch crates (`aarch64-cpu`). Neutral code calls only the `arch::` API. Keep `cargo kcheck-x86` passing.
- **Unsafe policy** (docs/safety-and-portability.md):
  - `unsafe` is denied crate-wide. A module may opt in only via `#[allow(unsafe_code)] // reason` on its `mod` line.
  - Prefer building a safe abstraction (`mmio::Region`, slot ownership, `PciRoot`) over spreading `unsafe`.
  - Every block needs `// SAFETY:` (denied otherwise), with one unsafe op per block.
  - `crates/*` are `#![forbid(unsafe_code)]`.
- `crates/*` are `#![no_std]` + `alloc` and **sans-IO** (pass bytes and `now` in; return bytes and events). Protocol logic goes there, not in the kernel.
- Dependencies must be `no_std`. Prefer audited crates (virtio-drivers, safe-mmio, smoltcp, aarch64-cpu) over hand-written unsafe.
- Edition 2024: `#[unsafe(no_mangle)]`, `unsafe extern "C"`, `&raw const`.
- Kernel runtime options are **boot arguments** (DTB `/chosen/bootargs`, QEMU `-append` via `QEMU_APPEND`), parsed in `config.rs`: `shape_up`, `shape_down`, `shape_overhead`, `shape_ingress=0` (download shaped on LAN egress as before 2026-11-19, which also caps traffic between networks: the lab's negative control for `lan to guest`), `ecn_up` (default 0: drop on upload), `ecn_down` (default 1: mark on download), `ecn` (sets both), `qdisc` (`cake` default, `fq_codel`, `codel` = single queue), `isolation` (`triple-isolate` default, `dual-srchost`, `dual-dsthost`, `flows`), `queue_ms` (a shaped queue's byte limit as time at its rate, default 100, `0` = the fixed 384 × 1514 B: `shaping.queue_ms`, `config::Qos::queue_limit`), `ack_filter=0|1` (CAKE's ACK filter on WAN egress, default off: `shaping.ack_filter`, `crates/qdisc/src/ack_filter.rs`), `queue_pkts=N` (every queue's packet limit, default `config::QUEUE_PACKETS` = 2048, byte ceiling N × 1514; boot argument only: the swarm check's negative control is `384`), `idle_spin_us`, `cores=N` (use at most N cores), `lan=a.b.c.d/len` (LAN subnet; pool .100–.199), `wan_vlan=N` (802.1Q tag on the WAN, `0` = untagged; `[wan] vlan`), `wan_pcp=0..7`, `wan_mode=pppoe|dhcp|static` (`[wan] mode`), `wan_ip=a.b.c.d/len`, `wan_gw=`, `wan_dns=a,b` (`[wan.static]`; without a stored one both `wan_ip=` and `wan_gw=` are needed), `pppoe_user=` (optional: empty = no authentication), `pppoe_pass=` (masked like `mgmt_pass=`), `pppoe_service=`, `pppoe_ac=`, `pppoe_mtu=` (`[wan.pppoe]`; - No heap use before `heap::init` (platform discovery runs before it). On x86_64, firmware memory (`platform::phys` views) is only valid during discovery: copy what you need into `BootInfo` or statics.
- New MMIO must be mapped in `mm::mmu::init` (or `arch::mmu::PLATFORM_MMIO`), or at runtime with `mm::mmu::map_device` (PCI BARs). Writable memory is never executable.
- Device interrupts: INTx where the platform routes it (aarch64), else MSI-X (`Pci::enable_msix`, vectors from `arch::irqchip::msi_vector`). Never add IOAPIC/INTx routing that needs ACPI AML.
- **Latency-first datapath (CAKE):** the qdisc is the only place packets may wait (no other FIFOs). TX is pull-based (`can_transmit` before `transmit`). Timers are tickless, so no periodic tick. Datapath tasks run at `Priority::Datapath`; router-local work (smoltcp, DHCP, DNS, mgmt, future services) runs in `Priority::Service` tasks and reaches the datapath only through `net::shared` (`spin::Mutex` + atomics, no `RefCell`, so tasks can move to other cores). Forwarded packets never leave the datapath task.
- **Ports:** NAT uses 10000–39999 (skipping forwarded ports); router-local client sockets (SNTP 60000–60999, DNS upstream 61000–65535 with a fresh random port per query, `services::Upstream`, DoT TCP 61000–64999, future ones) must bind ≥ 60000 (`fwd::forwarder::ROUTER_CLIENT_PORTS`; TCP replies pass only from `Policy::router_tcp_peers`) so replies are never mistaken for NAT or port-forward traffic; UDP from outside reaches only bound client ports (`net::shared::CLIENT_PORTS` → `fwd::forwarder::ClientPorts`; 68 only from 67, 546 only from 547), the rest is dropped silently, so the stack answers no scan with port unreachable; port forwards may use anything below 60000 (validated).
- Never edit a script in place while it may be running (bash reads scripts incrementally): write a temp file and rename it over the original.
- Measurements must prove the load or condition actually happened (validity checks), or be reported as invalid.
- New lab checks need a **negative control** (show that the check fails when the feature is broken), as done for the firewall probe.
- **Packet buffers** come only from `net::packet` (bounded pool, no allocation per packet). On pool exhaustion, drop; never grow.
- **IRQ handlers** (`irq::register` actions) only acknowledge or mask hardware and touch atomics. No allocation, no `println!`, no locks except ones thread context takes with IRQs masked (the irqchip lock). Work runs in tasks awaiting an `IrqEvent`. Device interrupts follow NAPI: mask → poll until empty → unmask. INTx lines may be shared (QEMU `virt`: slots 4 and 8 on one line with three igbs): `irq::register` takes up to 4 sharers with one action, signals every sharer's event, and the line is unmasked only when `irq::line_done` says every sharer drained its device.
- Timer precision under QEMU/HVF comes from **hybrid idle** (`timer::set_spin_window`, 4 ms on virtual machines, 0 on hardware). Don't add other workarounds for `wfi` latency; `idle-poll` is only for experiments.
- Network changes on the developer's Mac: mac-lab only adds lab-scoped routes and resolvers. mac-internet may change routing and DNS, but only after confirmation, with the original state saved first, `/1` routes (never the default route), a watchdog, and `--restore`. Keep these guarantees in any new script.
- Lab downloads are pinned by SHA-256 in `scripts/lab/fetch-alpine.sh`; never unpin. Update the hashes deliberately.
- Shell scripts must run on macOS bash 3.2 (no associative arrays) and BSD tools (no `\s` in sed, no `timeout`).
